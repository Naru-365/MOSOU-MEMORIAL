1. プロジェクト概要

「妄想メモリアル（妄メモ）」は、会話型オープンワールド × 立ち絵会話シミュレーションです。 「立ち絵で会話するだけ」という一見“縛りの強い”枠に、生成AIの「会話の自由度」と「画像生成の自由度」 を持ち込んで、枠の中の自由を楽しんでもらうのが狙い。

コアの体験

  • 実体のない状態から始まる：最初ヒロインは姿を持たない（立ち絵なし、テキストだけ）。
  • 会話でキャラメイク：約 10ラリーの会話で好み（外見・性格・呼び名・雰囲気）をヒアリング → gpt-image-2 で画像生成 → 立ち絵が初めて確定（最初のキャラメイク完成）。
  • 見た目が会話の中で変わる：美容院で髪型が変わる／服を買う／歳を取る／過去へタイムスリップで若返る／「実は犬だった」みたいな飛躍まで。identity（その子であること）は保ちつつ外見属性は意図的に変える。
  • 邪魔者乱入：恋愛シム＋ギャグ乱入は、このワールドの“イベント/NPC”として継続。

※ 現状のビルドはこのコンセプトの PoC サブセットです。「実体なし→10ラリーでキャラメイク」「外見の動的変化」は 実装(beta) — コードは完成、実機ブラウザ検証はこれから。画像生成には OPENAI_API_KEY が必要。未設定時はシルエット表示で動作します。

このPoCで検証したいこと

  • 縛りの強い立ち絵会話で、生成AIの会話＋画像生成の自由度が“面白さ”になるか
  • 会話ヒアリング → 画像生成でキャラメイクが成立するか（10ラリーの肌感）
  • 外見を動的に変えても identity（その子らしさ）を保てるか（gpt-image-2 の Edits）
  • 邪魔者の「乱入頻度」とセリフのキャラ立ちのチューニング感
  • Gemini APIで「セリフ生成」と「好感度ジャッジ」を1コールで賄えるか

3. 実装されている機能

👤キャラクター管理

  • 名前・性格（優しい／クール／ツンデレ）・見た目（清楚系／ギャル系／ナチュラル）
  • 一覧 / 新規作成 / 編集 / 削除
  • 削除時にチャット中のキャラなら状態リセット

画面: /characters

👁️‍🗨️邪魔者CRUD

  • 名前・タイプ（ツッコミ／束縛／メタ／カスタム）・説明
  • メッセージテンプレ複数行（{char} {user} {topic} スロット対応）
  • 有効化トグル、出現確率スライダー
  • デフォルト3体プリセット、リセットボタンあり

画面: /interrupters

🎯複合トリガ

邪魔者ごとに OR条件で発火条件を設定可能：

  • 嫉妬度しきい値 (≥ N)
  • Nターンごとの周期
  • キーワード一致（「好き」「デート」など）
  • ↑ いずれかが成立した上で出現確率ロール

💬Gemini自由会話

  • 自由テキスト入力でヒロインと会話
  • 好感度・嫉妬度はGeminiがユーザーの発言内容で判定
  • 邪魔者乱入時もGeminiが乱入セリフを生成
  • 1リクエストで {reply, affinityChange, jealousyChange, emotion} を取得
  • サーバ側でクランプ [-15, +15]

エンドポイント: POST /api/chat ／ モデル: gemini-2.5-flash

😊動的表情

  • Geminiが返す emotion でキャラ画像が即座に切り替わる
  • 8表情対応: neutral / happy / tsun / blush / angry / surprised / laugh / sad
  • 画像未配置時は名前イニシャル円にフォールバック（壊れない）

⚙️設定

  • プレイヤー名（ヒロインのセリフの {user} に差し込み）
  • 邪魔者管理ページへのリンク
  • ゲームのみリセット ／ 全データリセット

画面: /settings

🎨アセット解決抽象化

getCharacterAsset(character, emotion, mode) が image | video | 3d の3モードを単一APIで解決。 画像が来たらフォルダにドロップするだけで動く。 

/images/characters/seiso/happy.png
/images/characters/seiso/angry.png
/images/interrupters/tsukkomi/intro.png

💾永続化

  • Zustand persist（localStorage）
  • v3マイグレーション付き、古いキャッシュも壊れずアップグレード
  • 「全データリセット」で完全初期化可能
  • base64画像は localStorage 容量節約のため保存対象外（リロード後に再生成）

🌱会話キャラメイク 実装(beta)

  • キャラ作成時は「実体なし（シルエット）」からスタート
  • 約10ラリーの会話でヒロインが好み（外見・髪・服・性格・呼び名）をヒアリング
  • ヒアリング完了後、POST /api/generate-look で gpt-image-2 による初回立ち絵を生成
  • 生成完了で phase が onboarding → playing に切り替わり、立ち絵が確定
  • OPENAI_API_KEY 未設定時はシルエットのまま playing に移行（ゲームは止まらない）

画面: /characters/new → /chat ／ エンドポイント: POST /api/chat（phase=onboarding）

🔄外見の動的変化 実装(beta)

  • 外見を lookId 単位で管理。各 Look はメタデータ・属性・生成画像・参照画像を保持
  • 会話中のキーワードを detectLookChange() が検出し外見変更イベントを発火
  • 変更トリガ例：美容院→髪型 / 服→服装 / 歳を取る→加齢 / タイムスリップ→若返り / 犬→種族変化
  • 変更時は前 look の neutral 画像を参照画像として images.edit に渡しアイデンティティを維持
  • mergeLookAttributes() で属性差分をマージし、変わらない属性は前 look から引き継ぐ

エンドポイント: POST /api/generate-look（referenceImage あり = edits モード）

5. デモの遊び方

所要時間：5〜10分

  1. 初回アクセス時の注意
    古い保存データが残ってる可能性があるので、最初に 設定 → すべてのデータをリセット を一度押すと安全です。
  2. タイトル画面 → 「はじめる」
    桜色のボタンをタップ。
  3. キャラクターを作成
    右上の ＋ から新規作成。
    例：名前「ことね」／ 性格「ツンデレ」／ 見た目「清楚系」（画像が用意されてるのは清楚系のみ）。
  4. 「チャットを始める」
    キャラ詳細画面の桃色ボタンから。
  5. 自由テキストで話しかけてみる
    例：「はじめまして」「今日いい天気だね」「好きな食べ物は？」など。
    1〜3秒の「考え中…」のあと、ヒロインが返事をします（Geminiが性格・好感度に応じて生成）。 返事と同時にヘッダー横の好感度（💖）が動きます。
  6. 表情の切り替わりに注目
    優しい言葉を続けると好感度が上がり、キャラが happy や blush に。
    冷たく扱うと tsun や sad に。
  7. 邪魔者乱入を観察
    会話を続けると（特に「好き」「デート」などのキーワードや、嫉妬度が50超えた時に）、 赤い吹き出しで 「邪魔キャラ乱入!」 が割り込みます。
    そのまま自由テキストで邪魔者にも返答できます。
  8. 邪魔者をカスタマイズ
    設定 → 邪魔者を管理 から、出現確率・キーワード・セリフテンプレを編集できます。
    新しい邪魔者を作ることもできます。
  9. プレイヤー名を設定
    設定 → プレイヤー名 に名前を入れると、ヒロインのセリフ中の {user} がその名前に差し変わります。

触ってほしいポイント

  • セリフのトーン：性格別の喋り分けが効いてるか、ギャグ寄りに振れてるか
  • 好感度の動き方：あなたの発言の良し悪しを適切に拾えてるか
  • 邪魔者の頻度感：多すぎ／少なすぎないか（編集で調整可）
  • 表情の切替タイミング：違和感ないか
  • レイテンシ：1〜2秒の待ちが許容できるか

7. 今後の予定

  1. Phase 1 完了（実写画像）：ヒロインの不足3表情を gpt-image-2 の参照画像固定で生成・配置 → 邪魔者2体ぶんの画像生成 → 完全状態でのテストプレイ
  2. 会話キャラメイク：実体なしで開始 → 約10ラリーで好みヒアリング → gpt-image-2 で立ち絵確定（リファレンス顔も確定）。現状のフォーム入力を置換。実装(beta) — 実機検証・プロンプト調整これから
  3. 外見の動的変化：見た目を lookId 単位で管理し、美容院/買い物/加齢/タイムスリップ/種族変化のイベントで images.edit に直前 look を参照画像として渡し差分生成。identity は保ち外見だけ更新。実装(beta) — 実機検証・プロンプト調整これから
  4. UIリプレース：v0 でガラッと作り直し（ロジック層は触らない）
  5. Phase 2（飛ばし候補）：短尺動画ループ。乱入演出のカットインだけ部分採用は検討
  6. Phase 3：VRM / Three.js + R3F / Ready Player Me 等で現行3D化（vibe coding 待ちは不要）
  7. Phase 4：gpt-image-2 をランタイムで叩き、画像をオンザフライ生成（Responses API のマルチターン編集で同一人物のまま表情/シーンを動的生成）。動画／3Dも将来視野

8. 既知の制約・注意

UI

  • 現状のUIは 「捨て前提」 で組まれています。ロジック動作確認用と割り切ってください。
  • ヒーロー画像エリアが縦長／余白の取り方が雑なのは意図的（差し替え前に磨かない）。

LLM

  • 1ターンのレイテンシは1〜2秒。ストリーミング未対応。
  • レート制限なし（PoCのため）。本番化時は要対策。
  • セーフティ：システムプロンプトで成人向け／暴力的内容を禁止しているが、Gemini側のフィルタも併用。
  • たまにGeminiがJSONを返さずエラーになる場合あり（リトライしてください）。

画像

  • キャラ画像は gpt-image-2 で生成。neutralをリファレンス顔にして images.edit の参照画像に渡し、表情差分を生成している（入力は常に高忠実度処理）。
  • ※OpenAI公式も「recurring character の一貫性は複数生成で揺れ得る」と明記。ブレたらリファレンスを作り直す運用。
  • 現状の生成は事前生成→public/ に配置する運用。ランタイム生成（オンザフライ）はPhase 4。
  • ヒロインは 清楚系のみ 用意。ギャル系／ナチュラルを選ぶとフォールバック表示になります。
  • 邪魔者の画像はツッコミ部長のみ。夜々子・メタくんはアイコン代替。
  • 背景画像は配置済みですがチャット画面では現状未使用。

データ

  • localStorage を使うので、ブラウザのプライベートモードや履歴クリアでデータ消失します。
  • サーバー側にはユーザーデータは一切保存されていません（Gemini API呼び出しのみ）。
