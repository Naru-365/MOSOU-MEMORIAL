『妄想メモリアル』ってどんなゲーム？

約2分
ねらい：今日いちばんの“バズ”ポイント。コンセプトを体験として語る
ここが山場（厚めに）

ジャンルでいうと「会話型オープンワールド × 立ち絵会話シミュレーション」のPoCです。…って言われてもピンと来ないと思うので、体験を話します。

ゲームを始めると、最初は「実体のない子」がいます。顔も姿もない。そこからプレイヤーが話しかけて、10回くらい会話のラリーを重ねると、AIがその子のキャラクターを生成してくれる。会話の中身に応じて、見た目が立ち上がってくるんです。

面白いのはここからで、会話を続けると外見が動的に変わっていく。髪型が変わったり、服が変わったり、急に10歳年を取ったり…そして、ずっと話してたら「この子、実は犬だった」みたいなことが起きる（笑）。これがタイトルの伏線回収です。

裏側のコンセプトは「アイデンティティ（＝顔）は固定、ルック（＝見た目）は可変」。同じ存在なんだけど、関係性によって姿が変わる。そこを技術的に分離して作っているのがミソです。

スライドに載せるもの
コンセプト1枚
  • ジャンル：会話型オープンワールド × 立ち絵会話シミュレーション（PoC）
  • 体験フロー：実体のない子 → 約10ラリー → AIがキャラ生成 → 会話で外見が動的変化（髪型 / 服 / 年齢 / 種族…実は犬）
  • 設計思想：顔＝固定 / 見た目＝可変（identity と look の分離）
  • ※可能なら変化の前後スクショを2〜3枚並べる〔画像差し込み枠〕

どう作ったか ― AI 4体で“分業”

約2分
ねらい：エンジニア／推進部に刺さる中身。「人間が書いたのは一部」を強調
技術が好きな人向けのヤマ

作り方が今っぽくて。4つのAIに役割分担させて作りました。

まず見た目のUIは v0（Vercel）。ゲームのロジックは Claude Code に書かせる。ゲーム内でキャラがしゃべる“脳”は Gemini 3.5 Flash（軽量で速い会話モデル）。そしてキャラの画像は gpt-image-2（OpenAIの画像モデル）で生成しています。

外見が変わる仕組みがちょっと賢くて、直前の立ち絵を“リファレンスの顔”として渡して、「同じ人のまま、髪型だけ変えて」「10歳年上に」「犬にして」と編集指示を出す。だから別人にならずに、地続きで姿だけ変わるんです。

会話のAIは、1回の呼び出しで「セリフ・好感度の変化・嫉妬の変化・感情」をまとめてJSONで返すように作っていて、それでキャラの態度がリアルタイムに動きます。

最近は保存まわりも作り込んでいて、キャラ・会話・生成した立ち絵を Supabase（クラウドのDB＋ストレージ）に保存するようにしました。これで別の端末でも続きから遊べるし、立ち絵も一度作ればクラウドに残るので、開くたびに作り直さなくて済みます。書き込みはサーバー経由で、キーはサーバー側だけが持つ作りにしています。

規模感でいうと、開発約12日 / 20コミット、自分で書いたコードは約3,238行、生成した画像は10枚くらい。正直、人間が手で書いた部分はそのうちの一部で、あとはAIに任せた、というのが実感です。

スライドに載せるもの
AI分業の図 ＋ 数字
  • v0：UI ／ Claude Code：ゲームロジック ／ Gemini 3.5 Flash：会話の脳 ／ gpt-image-2：立ち絵生成
  • 外見変化：直前の立ち絵を参照顔として images.edit に渡し「同一人物のまま変化」
  • 会話：1コールで { reply, affinityChange, jealousyChange, emotion } を構造化JSON出力
  • データ保存：キャラ・会話・立ち絵を Supabase（DB＋ストレージ）に保存し、端末をまたいで続きから（device_id ごとに同期）
  • 技術スタック（小さく）：TypeScript / Next.js 16 / React 19 / Tailwind v4 / Zustand / Supabase
開発 約12日 20コミット 自作コード 約3,238行 生成画像 10枚 クラウド保存（Supabase）
コスト小ネタ（時間あれば）：立ち絵1枚は安いと約$0.005、高解像度（1024×1536）で約$0.165。表情8種そろえても高解像で$1.3くらい、と“財布に優しい”話を一言。

作ってみて気づいたこと（→ 仕事に着地）

約1.5分
ねらい：趣味を仕事（Copilot推進・AIX）にきれいにつなげる
話す内容

趣味の話なんですが、作ってみて仕事に直結する学びが3つありました。

1つめ。AIに“役割分担”させると一気に進む。1個のAIに全部やらせるより、UI・ロジック・会話・画像で分けたほうが圧倒的に速い。これ、業務でCopilotやエージェントを設計するときと同じ発想だなと。

2つめ。出力を構造化（JSON）で縛ると安定する。「いい感じに返して」じゃなくて、返す“型”を決める。これは社内の活用相談でもそのまま使える勘所でした。

3つめ。個人でここまで作れる時代だということ。週末に1人で、しかも安く、動くものができる。だからこそ「現場の人がAIで自分の業務を作り変える」推進をやる価値がある、と改めて思いました。

推進する側だった自分が、AIXで“作る側”を体験して、両方の気持ちがわかるようになった。これを社内のCopilot推進にも持ち帰りたいです。

業界の流れ（おまけ・1分で）

あと、今回あえて会話の脳に Gemini 3.5 Flash っていう“軽量で賢い”モデルを選んだんですが、ここに最近の大きな流れを感じています。

巨大モデルを競う時代から、「軽くて、速くて、賢い」AIが主役になりつつある。たとえばGoogleは2026年3月に TurboQuant という圧縮技術を出していて、LLMを動かすのに必要なメモリを約1/6に圧縮できる。賢さはそのままに、どんどん“軽く”できるようになってきているんです。

しかも足元では量子チップ「Willow」みたいな計算基盤の進化も同時に進んでいて、AIを支える土台そのものが強くなっている。

その軽量AIがどこへ向かうかというと、ゲームやロボット ── いわゆる“フィジカルAI”にAIが乗っていく流れです。実際Googleは Gemini Robotics On-Device という、ネット接続なしでロボットの中だけで動く軽量モデルを出していて、ロボットが現場で自律的に動き始めている。

僕が今回ゲームでやった「会話で姿が変わる」体験も、その大きな流れの“ゲーム側の入り口”だと思っていて。軽量AIが画面の中からリアルの世界に出ていく、その輪郭がはっきりしてきた時代に、自分も手を動かせているのが面白いなと感じています。
